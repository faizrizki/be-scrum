# Deployment: Vercel + Supabase

Panduan deploy **backend Laravel** (repo ini, `be-scrum`) dan **frontend
Next.js** (`../fe-project-management`) ke Vercel, dengan database PostgreSQL di Supabase,
plus **keep-alive harian** supaya project Supabase free tier tidak di-pause.

```
                    Vercel Cron (harian)  +  GitHub Actions (cadangan)
                                  |
                                  v
  Browser --> fe-project-management.vercel.app  (Next.js)
                                  |  NEXT_PUBLIC_API_URL
                                  v
              be-scrum.vercel.app  (Laravel, runtime vercel-php)
                                  |  Connection Pooler :6543
                                  v
                        Supabase PostgreSQL
```

> **Kenapa perlu keep-alive?** Project Supabase di plan Free otomatis **di-pause
> setelah 7 hari tanpa aktivitas**. Cron harian di bawah menembak endpoint
> `GET /api/keep-alive` yang melakukan UPDATE + SELECT ke tabel `keep_alive`,
> jadi selalu ada aktivitas tiap hari.

## Langkah 1 — Buat Project Supabase

1. Login ke https://supabase.com/dashboard → **New project**.
2. Isi:
   - **Name**: `project-management`
   - **Database Password**: buat password kuat, **simpan** (dipakai di `DB_PASSWORD`)
   - **Region**: pilih terdekat, mis. `Southeast Asia (Singapore)`
3. Tunggu provisioning selesai (~2 menit).

### Ambil connection string

**Project Settings → Database → Connection string → pilih tab `PSQL` / `URI`**,
lalu perhatikan bagian **Connection pooler**.

Untuk project yang dipakai sekarang (`pggcdtegeyxjkhiynkgk`, region
`ap-southeast-1`) nilainya sudah dipastikan:

| Mode | Host | Port | Dipakai untuk |
|---|---|---|---|
| **Session pooler** | `aws-0-ap-southeast-1.pooler.supabase.com` | `5432` | Migration & seeder dari laptop |
| **Transaction pooler** | `aws-0-ap-southeast-1.pooler.supabase.com` | `6543` | Runtime aplikasi di Vercel (serverless) |

Username: `postgres.pggcdtegeyxjkhiynkgk` — database: `postgres`.

Satu-satunya yang masih harus diambil manual adalah **Database password**
(Project Settings → Database → *Reset database password* kalau lupa), lalu isi
`DB_PASSWORD` di `.env.production` dan `.env.supabase`.

> Jangan pakai **Direct connection** (`db.<ref>.supabase.co`) — di free tier
> host itu IPv6-only dan sering tidak bisa diakses dari laptop/Vercel.

## Langkah 2 — Query yang dijalankan di Supabase

Buka **SQL Editor** di dashboard Supabase (menu kiri) → **New query**, lalu
jalankan query berikut berurutan.

### 2.1 Cek koneksi & versi

```sql
select version(), current_database(), current_user, now();
```

### 2.2 Bikin skema tabel

Ada **dua cara**, pilih salah satu.

**Cara A (disarankan) — lewat migration Laravel dari laptop.**
Skema jadi satu sumber kebenaran di `database/migrations`. Lompat ke
[Langkah 3](#langkah-3--migrasi--seed-dari-laptop-ke-supabase), lalu balik ke 2.3.

**Cara B — manual lewat SQL Editor.** Hanya kalau PHP/Composer tidak tersedia
di laptop. Repo ini sudah menyediakan skema lengkapnya di
**`database/supabase_schema.sql`** — buka file itu, salin seluruh isinya ke SQL
Editor, jalankan. Setelah itu tambahkan tabel keep-alive:

```sql
create table if not exists public.keep_alive (
  id         bigserial primary key,
  pinged_at  timestamp(0) null,
  ping_count bigint not null default 0
);

insert into public.keep_alive (id, pinged_at, ping_count)
values (1, now(), 0)
on conflict (id) do nothing;
```

> Catatan: `supabase_schema.sql` memakai tipe `timestamptz` dan
> `generated by default as identity`, sedangkan migration Laravel menghasilkan
> `timestamp(0)` dan `bigserial`. Fungsional sama, tapi kalau nanti menjalankan
> `php artisan migrate` di database yang sama, tabel `migrations` belum terisi
> sehingga Laravel akan mencoba membuat ulang tabel yang sudah ada. Pilih salah
> satu cara, jangan dicampur.

### 2.3 Verifikasi tabel sudah terbentuk

```sql
select table_name
from information_schema.tables
where table_schema = 'public'
order by table_name;
```

Harus muncul: `activities`, `attachments`, `cache`, `cache_locks`, `comments`,
`failed_jobs`, `job_batches`, `jobs`, `keep_alive`, `migrations`,
`notifications`, `personal_access_tokens`, `projects`, `sessions`, `tasks`,
`users`.

### 2.4 Cek data awal

```sql
select id, name, email, role from public.users order by id;
select * from public.keep_alive;
```

### 2.5 Query untuk memantau keep-alive (dipakai rutin)

```sql
-- Kapan terakhir di-ping dan sudah berapa kali
select id,
       pinged_at,
       ping_count,
       now() - pinged_at as sejak_terakhir_ping
from public.keep_alive
where id = 1;
```

Selama `sejak_terakhir_ping` selalu di bawah ~1 hari, project aman dari pause.

### 2.6 Kunci akses publik ke tabel (WAJIB)

Supabase mengekspos **seluruh schema `public` lewat REST API (PostgREST)**.
Tabel yang dibuat migration Laravel tidak punya Row Level Security, jadi tanpa
langkah ini isi tabel `users` — termasuk hash password — bisa dibaca siapa pun
yang punya *publishable key* (key itu memang dirancang untuk ditaruh di
frontend).

Sudah ditangani migration `2026_09_04_000001_enable_row_level_security`: semua
tabel di-`enable row level security` **tanpa policy**, sehingga role `anon` dan
`authenticated` tidak bisa membaca apa pun. Laravel tidak terpengaruh karena
konek sebagai role `postgres` yang punya `BYPASSRLS`.

Verifikasi statusnya:

```sql
select relname, relrowsecurity
from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relkind = 'r'
order by relname;
```

`relrowsecurity` harus `t` untuk semua tabel. Uji dari luar — harus balik `[]`:

```bash
curl "https://pggcdtegeyxjkhiynkgk.supabase.co/rest/v1/users?select=*" \
  -H "apikey: sb_publishable_..."
```

> Kalau nanti menambah tabel lewat migration baru, tabel itu **tidak otomatis
> ter-RLS**. Tambahkan namanya ke daftar di migration tersebut, atau jalankan
> `alter table nama_tabel enable row level security;`.

### 2.7 (Opsional) Ping manual dari SQL Editor

Kalau sewaktu-waktu mau memastikan ada aktivitas tanpa lewat API:

```sql
update public.keep_alive
set pinged_at = now(),
    ping_count = ping_count + 1
where id = 1
returning *;
```

> **Catatan soal `pg_cron`:** Supabase menyediakan extension `pg_cron`, tapi job
> yang jalan **di dalam** database tidak selalu dihitung sebagai "aktivitas
> project" oleh sistem auto-pause. Karena itu keep-alive di panduan ini memakai
> **request dari luar** (Vercel Cron + GitHub Actions) yang pasti terhitung.

## Langkah 3 — Migrasi & seed dari laptop ke Supabase

Sekali saja, dari mesin lokal:

`.env` lokal **tidak perlu diubah**. Repo ini sudah punya file `.env.supabase`
(sudah di-gitignore) yang menunjuk ke **session pooler port 5432**, dan Laravel
otomatis membaca `.env.<APP_ENV>` kalau `APP_ENV` diset sebagai environment
variable.

1. Isi `DB_PASSWORD` di `.env.supabase`.

2. Jalankan:

   ```bash
   APP_ENV=supabase php artisan migrate --force
   APP_ENV=supabase php artisan db:seed --force   # user demo: admin@test.com / admin123
   ```

   Windows (cmd):

   ```bat
   set APP_ENV=supabase && php artisan migrate --force
   set APP_ENV=supabase && php artisan db:seed --force
   ```

   > Port **5432** (session mode), bukan 6543. Migration butuh prepared
   > statement asli yang tidak jalan di transaction pooler.

   > **Jangan menaruh `APP_ENV=supabase` di dalam file `.env`.** Kalau `APP_ENV`
   > ikut terbawa ke proses anak (contohnya `php artisan serve` yang meneruskan
   > environment ke PHP built-in server), Laravel akan memuat `.env.supabase`
   > alih-alih `.env`, dan errornya menyesatkan: *"fe_sendauth: no password
   > supplied"*. Isi `APP_ENV=local` di `.env`.

3. `APP_KEY` production sudah digenerate dan ada di `.env.production`
   (sama dengan yang dipakai `.env.supabase`). Kalau mau bikin baru:
   `php artisan key:generate --show`.

## Langkah 4 — Deploy Backend ke Vercel

Repo ini sudah berisi konfigurasi yang dibutuhkan:

| File | Fungsi |
|---|---|
| `api/index.php` | Entrypoint serverless; mengarahkan storage/log ke `/tmp` |
| `vercel.json` | Runtime `vercel-php`, routing semua request ke Laravel, definisi cron |
| `.vercelignore` | `vendor/` tidak diupload — Composer jalan di build Vercel |

Langkah:

1. https://vercel.com/new → **Import** repo `faizrizki/be-scrum`.
2. **Framework Preset**: `Other`. Build/Output/Install command **dikosongkan**
   (runtime PHP yang menangani `composer install`).

   > Runtime yang dipakai `vercel-php@0.9.0` (PHP 8.5). Jangan turunkan ke
   > `0.7.4` (PHP 8.3): `config/database.php` bawaan Laravel 13 memakai class
   > `Pdo\Mysql` yang baru ada sejak PHP 8.4.
3. **Environment Variables** — salin isi file **`.env.production`** (sudah
   berisi nilai final untuk project Supabase ini). Cara cepat: di halaman
   Environment Variables Vercel, paste seluruh isi file, Vercel akan mem-parse
   per baris. Pilih environment **Production + Preview**.

   | Key | Value |
   |---|---|
   | `APP_NAME` | `Project Management` |
   | `APP_ENV` | `production` |
   | `APP_KEY` | sudah terisi di `.env.production` |
   | `APP_DEBUG` | `false` |
   | `APP_URL` | domain backend hasil deploy |
   | `LOG_CHANNEL` | `stderr` |
   | `LOG_LEVEL` | `error` |
   | `DB_CONNECTION` | `pgsql` |
   | `DB_HOST` | `aws-0-ap-southeast-1.pooler.supabase.com` |
   | `DB_PORT` | `6543` |
   | `DB_DATABASE` | `postgres` |
   | `DB_USERNAME` | `postgres.pggcdtegeyxjkhiynkgk` |
   | `DB_PASSWORD` | password database Supabase |
   | `DB_SSLMODE` | `require` |
   | `DB_EMULATE_PREPARES` | `true` |
   | `SESSION_DRIVER` | `array` |
   | `CACHE_STORE` | `array` |
   | `QUEUE_CONNECTION` | `sync` |
   | `CORS_ALLOWED_ORIGINS` | domain frontend (isi setelah FE jadi) |
   | `CRON_SECRET` | sudah terisi di `.env.production` |

   > **`DB_PORT=6543` + `DB_EMULATE_PREPARES=true` wajib berpasangan.** Transaction
   > pooler tidak mendukung named prepared statement; flag itu bikin PDO memakai
   > emulated prepare (lihat `config/database.php`).
   >
   > **`CRON_SECRET`** dikenali khusus oleh Vercel: cron otomatis mengirim header
   > `Authorization: Bearer <CRON_SECRET>`, dan endpoint keep-alive menolak
   > request tanpa header itu.

4. **Deploy**, lalu tes:

   ```bash
   curl https://be-scrum.vercel.app/up
   curl -X POST https://be-scrum.vercel.app/api/login \
     -H "Content-Type: application/json" \
     -d '{"email":"admin@test.com","password":"admin123"}'
   curl -H "Authorization: Bearer <CRON_SECRET>" \
     https://be-scrum.vercel.app/api/keep-alive
   ```

   Respons keep-alive yang benar:

   ```json
   {"success":true,"data":{"database":"postgres","pingedAt":"...","pingCount":1}}
   ```

## Langkah 5 — Deploy Frontend ke Vercel

1. https://vercel.com/new → import repo `faizrizki/fe-project-management`.
2. **Framework Preset**: `Next.js` (terdeteksi otomatis).
3. **Environment Variables**:

   | Key | Value |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | `https://be-scrum.vercel.app/api` |

   > Perhatikan akhiran `/api` — `src/lib/axios.ts` memakai nilai ini sebagai
   > `baseURL` apa adanya.

4. **Deploy**, catat domainnya.
5. Balik ke project **backend** di Vercel → set `CORS_ALLOWED_ORIGINS` ke domain
   frontend tadi → **Redeploy** backend.

## Langkah 6 — Aktifkan Keep-alive

### 6.1 Vercel Cron (utama)

Sudah terdaftar di `vercel.json`:

```json
"crons": [{ "path": "/api/keep-alive", "schedule": "0 3 * * *" }]
```

Jadwal `0 3 * * *` = **03:00 UTC = 10:00 WIB tiap hari**. Setelah deploy, cek di
**Vercel → project backend → Settings → Cron Jobs**; di sana bisa **Run now**
untuk tes manual.

> Plan **Hobby** dibatasi maksimal **2 cron job** dan hanya granularitas harian —
> konfigurasi di atas sudah sesuai batas itu.

### 6.2 GitHub Actions (cadangan)

File `.github/workflows/keep-alive.yml` sudah ada. Di repo GitHub backend:
**Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|---|---|
| `KEEPALIVE_URL` | `https://be-scrum.vercel.app/api/keep-alive` |
| `CRON_SECRET` | nilai sama persis dengan yang di Vercel |

Tes lewat tab **Actions → Keep Supabase Alive → Run workflow**.

> GitHub menonaktifkan scheduled workflow kalau repo tidak ada commit selama
> 60 hari. Kalau itu terjadi, cukup aktifkan lagi dari tab Actions.

### 6.3 Verifikasi mingguan

Jalankan query [2.5](#25-query-untuk-memantau-keep-alive-dipakai-rutin) di
Supabase SQL Editor. `ping_count` harus naik tiap hari.

## Batasan yang perlu diketahui

1. **Upload attachment belum persisten.** `CommentController::store()` menyimpan
   file ke disk `public` (`storage/app/public`). Di Vercel folder itu ada di
   `/tmp` dan **hilang setelah function selesai**. Solusi: pindah ke Supabase
   Storage (S3-compatible), sekali setup:

   ```bash
   composer require league/flysystem-aws-s3-v3   # commit composer.json + composer.lock
   ```

   lalu set env di Vercel (kredensial dari **Project Settings → Storage → S3
   Access Keys**, dan bucket `attachments` dibuat sebagai *public bucket*):

   ```env
   FILESYSTEM_DISK=s3
   AWS_ACCESS_KEY_ID=...
   AWS_SECRET_ACCESS_KEY=...
   AWS_DEFAULT_REGION=ap-southeast-1
   AWS_BUCKET=attachments
   AWS_ENDPOINT=https://<project-ref>.storage.supabase.co/storage/v1/s3
   AWS_URL=https://<project-ref>.supabase.co/storage/v1/object/public/attachments
   AWS_USE_PATH_STYLE_ENDPOINT=true
   ```

   dan ganti `$file->store('attachments', 'public')` → `$file->store('attachments')`.

2. **Tidak ada queue worker & scheduler.** `QUEUE_CONNECTION=sync` (job jalan
   langsung dalam request). Saat ini belum ada job/schedule, jadi aman.

3. **Cold start** ±250 ms–1 s untuk request pertama setelah idle.

## Troubleshooting

| Gejala | Sebab & solusi |
|---|---|
| `SQLSTATE[26000] prepared statement "..." does not exist` / `already exists` | Pakai port 6543 tanpa `DB_EMULATE_PREPARES=true`. Set flag itu, atau pindah ke port 5432. |
| `SQLSTATE[08006] SSL required` | Set `DB_SSLMODE=require`. |
| `Connection timed out` saat migrate dari laptop | Memakai direct connection (`db.<ref>.supabase.co`, IPv6). Ganti ke session pooler port 5432. |
| `MissingAppKeyException` | `APP_KEY` belum diset di Vercel. Isi hasil `php artisan key:generate --show`. |
| 500 tanpa detail | Cek **Vercel → Deployments → Functions → Logs** (`LOG_CHANNEL=stderr`). Untuk debug sementara set `APP_DEBUG=true`, jangan lupa balikin. |
| Frontend kena CORS | `CORS_ALLOWED_ORIGINS` belum berisi domain FE, atau backend belum di-redeploy setelah env diubah. |
| Cron jalan tapi 401 | `CRON_SECRET` di Vercel dan di GitHub Secrets tidak sama. |
| `fe_sendauth: no password supplied` padahal `.env` sudah diisi | `APP_ENV` di `.env` menunjuk ke file env lain (mis. `.env.supabase`) yang `DB_PASSWORD`-nya kosong. Set `APP_ENV=local`. |
| Data tabel bisa dibaca lewat REST API Supabase | RLS belum aktif — jalankan migration `enable_row_level_security`, lihat langkah 2.6. |
| Project Supabase tetap ke-pause | Cek `ping_count` di query 2.5; kalau tidak naik, cek log Cron Jobs di Vercel dan tab Actions di GitHub. |
